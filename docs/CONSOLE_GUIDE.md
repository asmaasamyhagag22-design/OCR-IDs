# Fixed14 Console: تسطيب وتشغيل

الـ console موقع داخلي بيشتغل جنب الـ OCR service. بيعمل 3 حاجات:

- **قائمة المراجعة:** الموظف بيراجع فيها الحالات اللي القراءة فيها مختلفة عن الرقم المكتوب، والحالات اللي ما اتقراتش.
- **نظرة عامة:** المشرف بيشوف فيها الدقة الحقيقية، وهي بتتحسب مع كل قرار.
- **التقارير وسجل العمليات:** ملفات CSV لفرق البيانات، وسجل بكل عملية اتعملت.

**الـ console ما بيعدّلش أي حاجة في سجلات المتقدمين.** القرارات بتتحفظ في collections خاصة بيه: `ocr_reviews`، و`ocr_review_audit`، و`console_users`، و`console_sessions`.

## 1. المتطلبات

- نفس جهاز الشغل اللي عليه الـ OCR service و MongoDB وسيرفر الصور ([DEPLOYMENT_GUIDE.md](DEPLOYMENT_GUIDE.md)).
- Docker مع `docker compose` (نسخة 2.24 أو أحدث)، أو Python 3.11 لو هتشغّليه من غير Docker.
- إعدادات الاتصال بـ MongoDB وسيرفر الصور والـ engine بتتقري **تلقائياً** من
  `scripts/natid_ocr_pipeline_model_API_calling.py`، يعني نفس الإعدادات اللي الـ client بيستخدمها.
  لو عايزة تغيّري أي إعداد، حطيه في ملف الإعدادات (الجزء 2).

## 2. ملف الإعدادات (اختياري)

```bash
mkdir -p "$HOME/.config/fixed14"
```

```bash
[ -f "$HOME/.config/fixed14/console.env" ] || (umask 077; printf 'CONSOLE_HOST=127.0.0.1\nCONSOLE_PORT=8090\n' > "$HOME/.config/fixed14/console.env")
```

| المتغير | الافتراضي | معناه |
|---|---|---|
| `CONSOLE_HOST` | `127.0.0.1` | العنوان اللي الموقع بيسمع عليه. لو المراجعين هيفتحوه من أجهزة تانية على الشبكة الداخلية، حطي IP الجهاز على الشبكة، وافتحي البورت في الـ firewall للشبكة الداخلية بس. |
| `CONSOLE_PORT` | `8090` | البورت. |
| `CONSOLE_MONGO_URI`, `CONSOLE_MONGO_DB`, `CONSOLE_APPLICANTS_COLLECTION` | من الـ client | الاتصال بـ MongoDB. |
| `CONSOLE_MEDIA_HOST` | من الـ client | سيرفر الصور. |
| `CONSOLE_OCR_ENGINE_URL` | من الـ client | الـ engine، وبيتستخدم في زرار "اقرا تاني" وفي حالة الأنظمة. |
| `CONSOLE_TYPED_FIELD` | `National Id` | اسم حقل الرقم المكتوب في سجل المتقدم. |
| `CONSOLE_DISPLAY_FIELDS` | فاضي | حقول زيادة تظهر للمراجع، زي `Full Name`، ولو أكتر من حقل افصلي بينهم بفاصلة. |
| `CONSOLE_SESSION_HOURS` | `8` | المستخدم بيخرج لوحده بعد المدة دي. |
| `CONSOLE_COOKIE_SECURE` | `0` | حطيه `1` لو الموقع شغّال ورا HTTPS. |

## 3. التشغيل بـ Docker (المفضّل)

من فولدر الريبو:

```bash
docker compose build console
```

لو الـ engine شغّال أصلاً بأمر `docker run ... fixed14-engine` اللي في دليل التسليم:

```bash
docker compose up -d console
```

ولو عايزة تشغّلي الاتنين مع بعض بأمر واحد، شيلي الـ container القديم الأول، وحطي اسم الـ image في `.env`:

```bash
docker rm -f fixed14-engine
```

```bash
echo "OCR_IMAGE=$(bash scripts/phase4_service_docker.sh image)" > .env
```

```bash
docker compose --profile engine up -d
```

الاتنين بيشتغلوا في الخلفية، **ومش محتاجين أي terminal يفضل مفتوح**. ولو الجهاز عمل restart بيقوموا لوحدهم.

| المهمة | الأمر |
|---|---|
| الحالة | `docker compose ps` |
| آخر سطور في الـ log | `docker compose logs --tail 50 console` |
| إيقاف | `docker compose stop console` |
| تشغيل تاني | `docker compose start console` |
| تحديث بعد `git pull` | `docker compose build console && docker compose up -d console` |

### أول حساب (مدير النظام)

```bash
docker compose run --rm console python -m console create-user admin --role admin --name "مدير النظام"
```

هيطلب كلمة السر مرتين، ومش هتظهر على الشاشة. بعد كده افتحي `http://127.0.0.1:8090`، وضيفي المراجعين والمشرفين من صفحة **المستخدمين**.

## 4. التشغيل من غير Docker

```bash
python3.11 -m venv "$HOME/.venvs/fixed14-console"
```

```bash
"$HOME/.venvs/fixed14-console/bin/pip" install -r console/requirements.txt
```

```bash
"$HOME/.venvs/fixed14-console/bin/python" -m console create-user admin --role admin
```

```bash
set -a; . "$HOME/.config/fixed14/console.env"; set +a; "$HOME/.venvs/fixed14-console/bin/python" -m console serve
```

## 5. وضع العرض (بداتا اصطناعية)

ده للعرض قدام اللجنة، أو لتدريب الموظفين من غير ما يشوفوا بيانات حقيقية. بيشغّل قاعدة بيانات في الذاكرة فيها 6,000 متقدم اصطناعي، بنفس نسب أول تشغيل حقيقي، وصور بطاقات مرسومة ومكتوب عليها "عينة اصطناعية":

```bash
python -m console demo --port 8090
```

الحسابات: `admin` و`supervisor` و`reviewer`، وكلمة السر `demo-password`. وكل حاجة بتتمسح أول ما البرنامج يقفل.

## 6. طريقة المراجعة

1. **قائمة المراجعة**، وبعدين **راجع اللي بعده**، أو اضغطي `Enter`.
2. قارني الصورة بالصفين: **قراءة الـ OCR** و**اللي المتقدم كتبه**. الخانات المختلفة بتظهر بلون، وتحتهم معنى كل رقم: تاريخ الميلاد، والمحافظة، والنوع.
3. اختاري القرار بالأرقام من الكيبورد:

| المفتاح | القرار | معناه للدقة |
|---|---|---|
| `1` | قراءة الـ OCR صح، والمتقدم كتب غلط | الـ OCR صح |
| `2` | المكتوب صح، والـ OCR قرا غلط | الـ OCR غلط |
| `3` | الاتنين غلط، فبتكتبي الرقم الصح | الـ OCR غلط |
| `4` | بطاقة شخص تاني | الـ OCR صح |
| `5` | الصورة مش واضحة | محتاج صورة جديدة |
| `6` | مش وش البطاقة | محتاج صورة جديدة |

4. `Enter` بيحفظ ويفتح الحالة اللي بعدها، و`S` بيتخطّاها.
   - الصورة: `+` و`-` للتكبير والتصغير، و`R` للّف، و`0` يرجّعها لحجمها.
5. زرار **اقرا الصورة تاني بالموديل** بيبعت الصورة للـ engine، وبيعرض القراءة ودرجة الثقة.

لما مراجع يفتح حالة، بتتحجز باسمه 10 دقايق، عشان مراجعين اتنين ما يشتغلوش على نفس الحالة. والقرار بعد ما يتحفظ ما يتعدّلش غير من مشرف، وكل تعديل بيتسجّل في تاريخ الحالة.

## 7. الدقة بتتحسب إزاي

على مستوى المتقدم، وبنفس طريقة `scripts/team_accuracy_report.py`:

- **قبل المراجعة:** المطابق ÷ اللي اتقيّموا. ده حد أدنى.
- **المؤكدة:** (المطابق + الحالات المختلفة اللي المراجع أكد إن الـ OCR فيها صح) ÷ اللي اتقيّموا.
- **أعلى قيمة ممكنة:** المؤكدة + كل الحالات المختلفة اللي لسه ما اتراجعتش.
- **المتوقع:** نسبة "الـ OCR صح" في الحالات اللي اتراجعت، متطبّقة على اللي لسه ما اتراجعش، ومعاها هامش ثقة 95% (Wilson).

## 8. حماية البيانات

- الموقع للشبكة الداخلية بس، وكل صفحة محتاجة تسجيل دخول.
- القائمة بتعرض الأرقام متخبّية، والرقم الكامل بيظهر في شاشة المراجعة بس.
- الصور بتتعرض من سيرفر الصور مباشرة، ومش بتتحفظ على الجهاز ولا في المتصفح (`no-store`).
- كل فتح حالة، وكل قرار، وكل تصدير بيتسجّل في **سجل العمليات** باسم المستخدم ووقته، والسجل نفسه ما فيهوش أرقام قومية.
- ملفات **كل القرارات** و**تصحيح الرقم المكتوب** فيها أرقام قومية كاملة. اتعاملي معاها زي الـ client log بالظبط (جزء 12 في دليل التسليم).
