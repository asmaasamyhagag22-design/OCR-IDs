# منظومة مراجعة قراءة الرقم القومي (Fixed14 Console)
## دليل التشغيل والاستخدام

يشرح هذا الدليل تثبيت المنظومة وتشغيلها واستخدامها على جهاز العمل. وهو مكمّل لـ [دليل التسليم](DEPLOYMENT_GUIDE.md)، الذي يغطي خدمة القراءة الآلية والعميل الذي يعالج سجلات المتقدمين.

---

## 1. نظرة عامة

### 1.1 المكوّنات

| المكوّن | الوظيفة | المنفذ |
|---|---|---|
| **خدمة القراءة** (`fixed14-engine`) | تقرأ الرقم القومي من صورة البطاقة. لم يطرأ عليها أي تعديل. | `127.0.0.1:8081` |
| **خدمة فحص النموذج** (`fixed14-inspector`) | تعرض ما يراه النموذج: الشريط المقروء، وخريطة الانتباه لكل خانة، والثقة في كل خانة. | `127.0.0.1:8082` |
| **المنظومة** (`fixed14-console`) | موقع داخلي يضم المراجعة، ولوحة المتابعة، والتقارير، وسجل العمليات، وإدارة المستخدمين. | `127.0.0.1:8090` |

### 1.2 مسار البيانات

1. يقرأ العميل (`natid_ocr_pipeline_model_API_calling.py`) سجلات المتقدمين، ويرسل صورهم إلى خدمة القراءة، ثم يكتب النتيجة في الحقل `Auto Id_Validation`. هذا المسار لم يتغيّر.
2. تقرأ المنظومة هذه النتائج **دون أي تعديل على سجلات المتقدمين**، وتعرض على المراجِع الحالات التي تختلف فيها القراءة عن الرقم المُدخل، والحالات التي تعذّرت قراءتها.
3. تُحفظ قرارات المراجعة في مجموعات (collections) مستقلة:

| المجموعة | محتواها |
|---|---|
| `ocr_reviews` | قرار واحد لكل حالة، مع سجلّه الكامل. |
| `ocr_review_audit` | سجل عمليات يُضاف إليه فقط. |
| `console_users` | المستخدمون. |
| `console_sessions` | جلسات الدخول. |

### 1.3 الصلاحيات

| الصلاحية | ما تتيحه |
|---|---|
| مراجِع | قائمة المراجعة، وشاشة المراجعة، ولوحة المتابعة، وشاشة «داخل النموذج». |
| مشرف | كل ما سبق، إضافةً إلى التقارير والتصدير وسجل العمليات وتعديل أي قرار. |
| مدير النظام | كل ما سبق، إضافةً إلى إدارة المستخدمين. |

## 2. المتطلبات

- جهاز العمل نفسه الذي تعمل عليه خدمة القراءة وقاعدة البيانات MongoDB وخادم الصور.
- Docker مع `docker compose` (الإصدار 2.24 أو أحدث)، أو Python 3.11 للتشغيل دون Docker.
- تُقرأ إعدادات الاتصال بقاعدة البيانات وخادم الصور وخدمة القراءة **تلقائيًا** من ملف العميل `scripts/natid_ocr_pipeline_model_API_calling.py`، أي من الموضع الذي تُضبط فيه أصلًا، فلا حاجة إلى تكرارها.

## 3. ملف الإعدادات (اختياري)

```bash
mkdir -p "$HOME/.config/fixed14"
```

```bash
[ -f "$HOME/.config/fixed14/console.env" ] || (umask 077; printf 'CONSOLE_HOST=127.0.0.1\nCONSOLE_PORT=8090\n' > "$HOME/.config/fixed14/console.env")
```

| المتغيّر | القيمة الافتراضية | الوصف |
|---|---|---|
| `CONSOLE_HOST` | `127.0.0.1` | العنوان الذي تستمع عليه المنظومة. إذا كان المراجِعون سيدخلون من أجهزة أخرى على الشبكة الداخلية، فيُضبط على عنوان الجهاز في تلك الشبكة، ويُفتح المنفذ في الجدار الناري للشبكة الداخلية فقط. |
| `CONSOLE_PORT` | `8090` | المنفذ. |
| `CONSOLE_MONGO_URI`، `CONSOLE_MONGO_DB`، `CONSOLE_APPLICANTS_COLLECTION` | من ملف العميل | الاتصال بقاعدة البيانات. |
| `CONSOLE_MEDIA_HOST` | من ملف العميل | عنوان خادم الصور. |
| `CONSOLE_OCR_ENGINE_URL` | من ملف العميل | عنوان خدمة القراءة، ويُستخدم في «إعادة القراءة» وفي لوحة حالة الأنظمة. |
| `CONSOLE_INSPECTOR_URL` | `http://127.0.0.1:8082` مع Docker | عنوان خدمة فحص النموذج. إذا تُرك فارغًا عند التشغيل دون Docker، تظهر في الشاشة إرشادات التشغيل. |
| `CONSOLE_FOUND_IMAGES` | `/run/fixed14/found_front_images.json` مع Docker | ملف الصور المحفوظة خارج مسارها المسجّل (القسم 6). |
| `CONSOLE_MEDIA_ROOT` | `/var/www/html` | المجلد الجذري لخادم الصور على القرص، وهو نفسه `--root` في `team_download_problems.py`. |
| `CONSOLE_TLS_CERT`، `CONSOLE_TLS_KEY` | فارغ | لتشغيل المنظومة عبر HTTPS (القسم 7). |
| `CONSOLE_TYPED_FIELD` | `National Id` | اسم حقل الرقم المُدخل في سجل المتقدم. |
| `CONSOLE_DISPLAY_FIELDS` | فارغ | حقول إضافية تُعرض للمراجِع، مثل `Full Name`. إذا تعدّدت تُفصل بفواصل. |
| `CONSOLE_SESSION_HOURS` | `8` | مدة الجلسة قبل الخروج التلقائي. |
| `CONSOLE_COOKIE_SECURE` | `0` | يُضبط على `1` إذا كانت المنظومة تعمل خلف خادم HTTPS آخر. ويُفعَّل تلقائيًا عند ضبط `CONSOLE_TLS_CERT`. |

## 4. التشغيل عبر Docker (الطريقة الموصى بها)

### 4.1 تشغيل المكوّنات الثلاثة بأمر واحد

1. يُكتب في الملف `.env` داخل مجلد المستودع اسمُ صورة خدمة القراءة، والمستخدمُ الذي تعمل به المنظومة (مستخدم الجهاز نفسه، لتتمكن من قراءة ملفاته الخاصة):

```bash
echo "OCR_IMAGE=$(bash scripts/phase4_service_docker.sh image)" > .env
```

```bash
echo "CONSOLE_USER=$(id -u):$(id -g)" >> .env
```

```bash
mkdir -p "$HOME/.config/fixed14/console" && chmod 700 "$HOME/.config/fixed14/console"
```

2. إذا كانت خدمة القراءة تعمل حاليًا بالأمر `docker run ... fixed14-engine` الوارد في دليل التسليم، تُزال الحاوية القديمة حتى تتولاها `docker compose`:

```bash
docker rm -f fixed14-engine
```

3. تُبنى صورتا المنظومة وخدمة الفحص، ثم تُشغَّل المكوّنات الثلاثة:

```bash
docker compose --profile engine build
```

```bash
docker compose --profile engine up -d
```

تعمل المكوّنات في الخلفية، **فلا يلزم إبقاء أي نافذة طرفية مفتوحة**، وتعود إلى العمل تلقائيًا بعد أي توقف أو إعادة تشغيل للجهاز.

**بديل:** إذا كان المطلوب تشغيل المنظومة وحدها مع الإبقاء على خدمة القراءة الحالية كما هي:

```bash
docker compose up -d console
```

في هذه الحالة تظهر شاشة «داخل النموذج» مع رسالة تفيد بأن خدمة الفحص لا تستجيب، وتعمل بقية الشاشات كالمعتاد.

### 4.2 إنشاء الحساب الأول

```bash
docker compose run --rm console python -m console create-user admin --role admin --name "مدير النظام"
```

يطلب الأمر كلمة المرور مرتين دون أن تظهر على الشاشة. بعد ذلك:

1. يُفتح العنوان `http://127.0.0.1:8090`.
2. يُضاف المراجِعون والمشرفون من شاشة **المستخدمون**.

### 4.3 الفحص قبل الاستخدام

```bash
docker compose run --rm console python -m console check
```

يتحقق الأمر مما يلي:
- الاتصال بقاعدة البيانات، وصحة أسماء الحقول في سجلات المتقدمين؛
- إمكانية الكتابة في مجموعات المنظومة؛
- وجود حساب مدير؛
- إمكانية تحميل صورة نموذجية من خادم الصور؛
- ملف الصور المحفوظة في مواضع أخرى؛
- خدمة القراءة، وخدمة فحص النموذج.

ويطبع الأعداد والنتائج فقط، دون أي رقم قومي أو مسار.

- **النتيجة المطلوبة:** `"all_pass": true`.
- **`WARN`:** تنبيه لا يمنع التشغيل، مثل خدمة فحص لم تكتمل بعد، أو ملف صور غير موجود.
- **`FAIL`:** يجب حلّه قبل بدء المراجعة.

### 4.4 التشغيل اليومي

| المهمة | الأمر |
|---|---|
| حالة المكوّنات | `docker compose --profile engine ps` |
| آخر سطور سجل المنظومة | `docker compose logs --tail 50 console` |
| إيقاف المنظومة | `docker compose stop console` |
| إعادة تشغيلها | `docker compose start console` |
| التحديث بعد `git pull` | `docker compose --profile engine build && docker compose --profile engine up -d` |

## 6. الصور المحفوظة في مجلد غير المسجّل

هذه هي السجلات التي أعادت `team_download_problems.py` العثور على صورها (437 سجلًا في التشغيل الأول)، ثم قرأتها `team_reread_found_images.py`. المسار المسجّل في قاعدة البيانات ما زال خاطئًا، ولذلك تحتاج المنظومة إلى الملف `found_front_images.json` لتعرض الصورة الصحيحة على المراجِع:

```bash
install -m 600 "$HOME/found_front_images.json" "$HOME/.config/fixed14/console/found_front_images.json"
```

- تُعرض هذه الحالات في شاشة المراجعة بشارة «الصورة من موضع بديل».
- تُجلب الصورة من خادم الصور نفسه، بمسارها تحت `CONSOLE_MEDIA_ROOT`.
- يُرفض أي مسار يقع خارج هذا المجلد.
- يتضمن الملف أرقامًا قومية في مساراته، ولذلك يبقى بصلاحية `600`، ولا تطبعه المنظومة في أي موضع.
- إذا أُعيد تشغيل `team_download_problems.py` يُنسخ الملف من جديد، وتقرأ المنظومة النسخة الجديدة تلقائيًا.

## 7. التشغيل عبر HTTPS (اختياري)

يُستحسن هذا إذا كان المراجِعون سيدخلون من أجهزة أخرى على الشبكة الداخلية. ينشئ الأمر الآتي شهادة ذاتية التوقيع لعنوان الجهاز في الشبكة (مثال `10.0.0.5`):

```bash
openssl req -x509 -newkey rsa:3072 -nodes -days 825 -subj "/CN=fixed14-console" -addext "subjectAltName=IP:10.0.0.5" -keyout "$HOME/.config/fixed14/console/tls.key" -out "$HOME/.config/fixed14/console/tls.crt" && chmod 600 "$HOME/.config/fixed14/console/tls.key"
```

ثم تُضاف إلى `console.env` الأسطر التالية:

```
CONSOLE_HOST=10.0.0.5
CONSOLE_TLS_CERT=/run/fixed14/tls.crt
CONSOLE_TLS_KEY=/run/fixed14/tls.key
```

بعد إعادة التشغيل يصبح العنوان `https://10.0.0.5:8090`. وفي أول دخول يطلب المتصفح قبول الشهادة. ويُفتح المنفذ `8090` في الجدار الناري للشبكة الداخلية فقط.

## 8. النسخ الاحتياطي لقرارات المراجعة

يغطي النسخ الاحتياطي الوارد في دليل التسليم (القسم D2) مجموعة المتقدمين فقط. أما عمل المراجِعين فمحفوظ في مجموعات المنظومة، ويُنسخ بالأمر الآتي:

```bash
for c in ocr_reviews ocr_review_audit console_users; do mongodump --uri "mongodb://127.0.0.1:27017/" --db DEPI_R5_Applicant_DB --collection "$c" --out "$HOME/console_backup_$(date +%F)"; done; chmod -R go-rwx "$HOME/console_backup_$(date +%F)"
```

- **التوقيت المقترح:** يُنفَّذ يوميًا في نهاية العمل.
- **الجدولة:** يمكن جدولته بإضافة سطر إلى `crontab -e`. مثال للتنفيذ يوميًا الساعة السادسة مساءً:

```
0 18 * * * for c in ocr_reviews ocr_review_audit console_users; do mongodump --quiet --uri "mongodb://127.0.0.1:27017/" --db DEPI_R5_Applicant_DB --collection "$c" --out "$HOME/console_backup_$(date +\%F)"; done
```

**الاسترجاع** (لا يُنفَّذ إلا عند الحاجة، وبعد إيقاف المنظومة):

```bash
mongorestore --uri "mongodb://127.0.0.1:27017/" --nsInclude "DEPI_R5_Applicant_DB.ocr_*" --nsInclude "DEPI_R5_Applicant_DB.console_users" --drop "$HOME/console_backup_<التاريخ>"
```

ملفات النسخ الاحتياطي تتضمن أرقامًا قومية، وتُعامَل معاملة نسخة قاعدة البيانات نفسها.

## 9. شاشة «داخل النموذج»

تعرض هذه الشاشة، لأي حالة أو لأي صورة تُرفع إليها، ما يلي:

- **مسار المعالجة:** كيف حُدِّدت البطاقة، وهل عملت خطوات الاستدراك F1v وF8 وF9.
- **الشريط** الذي قرأه النموذج فعليًا، بمقاس 160×576.
- **المواضع الأربعة عشر** التي خصّصها النموذج للخانات.
- **خريطة الانتباه** لكل خانة على أعمدة الشريط، و**انتباه الصفوف**.
- **الاحتمال الأعلى والبديل الأقرب** لكل خانة، وتمييز **أضعف خانة**، وهي التي تحدد ثقة الرقم كله.

**ضمان المطابقة:** تُشغّل الشاشة خط المعالجة نفسه المستخدم في الإنتاج، بما في ذلك خطوات الاستدراك. ولا تبدأ الخدمة العمل إلا بعد أن تُعيد مخرجات النموذج على شريط الاختبار المختوم بفرق لا يتجاوز `1e-4`. ويُعرض الفرق الفعلي في كل نتيجة تحت عنوان «مطابق لنموذج الإنتاج»، وقد بلغ في الاختبارات نحو `1e-5`.

**الخصوصية:** الصورة المرفوعة تُقرأ في الذاكرة فقط، ولا تُحفظ في أي موضع.

## 10. وضع العرض

يُستخدم للعرض على اللجان ولتدريب الموظفين دون الاطلاع على بيانات حقيقية. يشغّل قاعدة بيانات في الذاكرة فيها 6,000 متقدم اصطناعي بنسب أول تشغيل فعلي، مع صور بطاقات مرسومة تحمل عبارة «عينة اصطناعية»:

على Windows (PowerShell)، ويُنشئ الأمر بيئة Python في المرة الأولى:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\console_demo.ps1
```

وعلى Linux أو WSL:

```bash
bash scripts/console_demo.sh
```

- **الحسابات:** `admin` و`supervisor` و`reviewer`، وكلمة المرور `demo-password`. تُمحى كل البيانات عند إغلاق البرنامج.
- **شاشة «داخل النموذج» في وضع العرض:** إذا لم تكن خدمة الفحص مشغّلة، تُعرض نتائج توضيحية مرسومة، وتُعلَّم بوضوح بأنها ليست صادرة عن النموذج. ولعرض النموذج الحقيقي، تُشغَّل الخدمة ويُضبط `CONSOLE_INSPECTOR_URL` قبل تشغيل وضع العرض.
- **ملاحظة مهمة:** البطاقات المرسومة لا تشبه البطاقة الحقيقية، ولذلك يخطئ النموذج الحقيقي في قراءتها. وهذا متوقَّع، وتُظهر شاشة «داخل النموذج» سببه بوضوح: يلتقط النموذج شريطًا غير شريط الرقم. **ولعرض أداء النموذج الفعلي، تُرفع صورة بطاقة حقيقية** (بموافقة صاحبها) في شاشة «داخل النموذج».

## 11. دليل المراجِع

1. من **قائمة المراجعة** يُضغط **مراجعة الحالة التالية**، أو مفتاح `Enter`.
2. تُقارَن الصورة بالصفّين: **القراءة الآلية** و**الرقم المُدخل**.
   - تظهر الخانات المختلفة باللون الكهرماني.
   - تحت الصفّين تظهر البيانات المستخرجة من كل رقم: تاريخ الميلاد، والمحافظة، والنوع، وصلاحية الرقم.
3. يُختار القرار بأرقام لوحة المفاتيح:

| المفتاح | القرار | أثره في الدقة |
|---|---|---|
| `1` | القراءة الآلية صحيحة، وأخطأ المتقدم في الإدخال | القراءة صحيحة |
| `2` | الرقم المُدخل صحيح، وأخطأت القراءة الآلية | القراءة خاطئة |
| `3` | كلاهما غير صحيح، ويُدخَل الرقم الصحيح | القراءة خاطئة |
| `4` | بطاقة شخص آخر | القراءة صحيحة |
| `5` | الصورة غير واضحة | يلزم طلب صورة جديدة |
| `6` | ليست الوجه الأمامي للبطاقة | يلزم طلب صورة جديدة |

4. مفاتيح الحفظ والتنقل:
   - `Enter` يحفظ القرار وينتقل إلى الحالة التالية.
   - `S` يتخطى الحالة، ويحرّرها للآخرين فورًا.
5. مفاتيح التحكم في الصورة:
   - `+` و`−` للتكبير والتصغير.
   - `R` للتدوير.
   - `0` لإعادة الصورة إلى حجمها الأصلي.
6. يمكن إدخال الرقم الصحيح بالأرقام العربية أو الهندية، فهي تُحوَّل تلقائيًا.

**تحجز الحالة** باسم المراجِع الذي فتحها مدة عشر دقائق، والحجز ذرّي، فلا يمكن أن يعمل مراجِعان على الحالة نفسها. ولا يُعدَّل القرار بعد حفظه إلا من المشرف، ويُحفظ كل تعديل في سجل الحالة.

## 12. احتساب الدقة

تُحتسب الدقة على مستوى المتقدم، وبالطريقة نفسها المتبعة في `scripts/team_accuracy_report.py`:

| المؤشر | طريقة الاحتساب |
|---|---|
| **قبل المراجعة** | الحالات المطابقة ÷ الحالات التي خضعت للتقييم. وهو حدٌّ أدنى. |
| **المؤكَّدة** | (المطابقة + الحالات المختلفة التي أكّد المراجِع صحة قراءتها) ÷ الحالات التي خضعت للتقييم. |
| **الحد الأعلى** | المؤكَّدة + جميع الحالات المختلفة التي لم تُراجَع بعد. |
| **المتوقعة** | تُطبَّق نسبة صحة القراءة في الحالات المحسومة على الحالات المتبقية، مع فترة ثقة 95% (Wilson). |

تُعدّ الحالات المطابقة صحيحة، إذ لا تكون خاطئة إلا إذا أخطأ النموذج والمتقدم في الأرقام الأربعة عشر نفسها.

## 13. التقارير والتصدير

| التقرير | محتواه | يتضمن أرقامًا قومية |
|---|---|---|

## 14. الأمان وحماية البيانات

- **سجلات المتقدمين** لا تُعدَّل إطلاقًا، وقد ثبت ذلك باختبار يقارن بصمة المجموعة قبل التشغيل وبعده.
- **الدخول:**
  - كل صفحة تتطلب تسجيل الدخول.
  - كلمات المرور مخزّنة بخوارزمية scrypt.
  - رموز الجلسات مخزّنة كبصمات SHA-256.
  - يُحظر الدخول خمس دقائق بعد خمس محاولات فاشلة.
- **حماية الطلبات:**
  - كل تعديل محمي برمز CSRF.
  - تُرسَل ترويسات أمان صارمة: CSP، و`no-store`، و`X-Frame-Options`.
- **الأرقام والصور:**
  - تظهر الأرقام في القوائم مُخفاة جزئيًا، ولا تظهر كاملة إلا في شاشة المراجعة.
  - الصور تُعرض من خادم الصور مباشرة، ولا تُحفظ على الجهاز ولا في المتصفح.
- **سجل العمليات:** كل فتح حالة وكل قرار وكل تصدير يُسجَّل فيه باسم المستخدم ووقته. والسجل نفسه لا يحتوي على أي رقم قومي.
- **الحاويات:** تعمل بمستخدم غير جذري (non-root)، وبنظام ملفات للقراءة فقط، ودون صلاحيات إضافية.
- **ملفات التصدير** التي تتضمن أرقامًا قومية تُعامَل معاملة سجل العميل (القسم 12 من دليل التسليم).

### 16.2 ما لم يتم التحقق منه بعد

- **خطوة `apt`:** تعذّر الوصول إلى مستودعات Debian في بيئة الاختبار، فاستُخدمت عند البناء نسخ الحزم نفسها (bookworm) من صورة Python الكاملة. ولذلك يُبنى على جهاز العمل بالأمر نفسه:

```bash
docker compose --profile engine build
```

- **Windows:** لم يُجرَّب وضع العرض على Windows. وقد ثبت أن ملف المتطلبات وحده يكفي، إذ نجحت الاختبارات في بيئة جديدة نظيفة.
- **صورة خدمة القراءة:** تحتوي pillow 10.4.0، ولها ثغرات منشورة تخص قراءة الصور. لم تُرفع في هذا العمل، لأن إصدارات الحزم في تلك الصورة مثبّتة ومتحقق منها بمخرجات النموذج المرجعية. رفعها قرار يعود إلى مالك المشروع، ويتطلب إعادة التحقق من المطابقة (القرار D-112).
